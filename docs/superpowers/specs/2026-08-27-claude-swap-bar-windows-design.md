# Claude Swap Bar for Windows — 설계 문서

작성일: 2026-08-27
상태: 승인됨 (구현 계획 대기)

## 1. 개요

`cswap`(claude-swap)을 위한 Windows 시스템 트레이 앱. 여러 Claude Code 계정의
사용량을 트레이 아이콘으로 상시 표시하고, 트레이 메뉴에서 한 번의 클릭으로
계정을 전환한다.

디자인은 macOS용 [claude-swap-bar](https://github.com/jx-grxf/claude-swap-bar)를
참고한다. 다만 참고 대상은 사용자에게 보이는 표현 방식(사용량 미터, 색상 코드,
리셋 카운트다운, 정직한 실패 표시)이며, 내부 구조는 따르지 않는다. 그 이유는
3절에 있다.

### 1.1 v1 범위

v1은 트레이 전용이다. 팝오버 창을 만들지 않는다.

포함:

- 트레이에 고정 아이콘 상주
- 툴팁에 현재 계정의 5시간/7일 사용률, 정확한 수치와 리셋 시각
- 트레이 메뉴에서 계정 목록 확인 및 클릭 전환
- Rotate(다음 계정) 및 Best Quota(잔여 한도가 가장 많은 계정으로 이동)
- 5분 주기 자동 갱신 및 수동 갱신
- Windows 시작 시 자동 실행 토글
- cswap 대시보드(TUI)를 새 터미널에서 열기

제외 (v2 이후):

- HTML/CSS 팝오버 UI
- `cswap auto` 백그라운드 자동 전환 토글
- Windows 토스트 알림
- 계정 추가/삭제, alias 편집, slot 순서 변경, 디렉토리 매핑

## 2. 기술 스택

- Rust + Tauri v2
- 트레이 아이콘과 네이티브 메뉴만 사용하며, v1에서는 WebView 창을 생성하지 않는다
- 아이콘은 정적 ICO 리소스이며 런타임 렌더링을 하지 않는다
- 배포: NSIS 설치본 + 포터블 exe

v1이 트레이 전용인데도 Tauri를 채택한 이유는 v2에서 팝오버 UI를 붙일 때
프레임워크를 갈아엎지 않기 위해서다. Tauri 런타임은 WebView2를 요구하지만
Windows 11에는 기본 탑재되어 있어 실질적인 부담이 없다.

전제 환경: rustc 1.97.1, cargo 1.97.1, Node 24.19.0 (확인 완료)

## 3. 아키텍처: cswap CLI 래퍼

macOS 앱은 Keychain 접근, OAuth 토큰 갱신, 사용량 API 폴링을 모두 자체
구현했다(`Vault.swift`, `OAuthService.swift`, `UsageService.swift`). Windows
에서는 그럴 필요가 없다. `cswap.exe`가 이미 자격증명 스위칭, 토큰 갱신, 사용량
조회를 수행하며 `--json` 플래그로 기계 판독 가능한 출력을 낸다.

따라서 이 앱은 cswap CLI의 래퍼로 만든다. 5분마다 `cswap list --json`을 호출해
파싱하고, 전환은 `cswap switch`에 위임한다.

이 선택으로 얻는 것:

- 자격증명 처리 코드를 한 줄도 작성하지 않는다
- cswap을 업그레이드하면 앱의 동작도 자동으로 따라간다
- cswap의 내부 저장소 포맷이 바뀌어도 앱이 깨지지 않는다

대가:

- 갱신 틱마다 프로세스를 스폰한다(측정값 약 1.3초)
- cswap 설치에 의존한다

검토했으나 채택하지 않은 대안은 cswap의 데이터 파일을 직접 읽고 Anthropic
사용량 API를 직접 호출하는 방식이다. 자격증명 경합과 토큰 갱신 레이스를 앱이
떠안게 되며, 이는 cswap이 이미 해결한 문제를 다시 푸는 일이다.

### 3.1 사용하는 cswap 명령

| 목적 | 명령 |
| --- | --- |
| 계정 목록 및 전체 사용량 | `cswap list --json` |
| 특정 계정으로 전환 | `cswap switch <num> --json` |
| 다음 계정으로 순환 | `cswap switch --json` |
| 잔여 한도 최대 계정으로 이동 | `cswap switch --strategy best --json` |
| 대시보드 열기 | `cswap tui` (새 터미널 창) |

`cswap status --json`은 사용하지 않는다. `list --json`의 응답에
`activeAccountNumber`와 각 계정의 `active` 플래그가 포함되어 있어 한 번의
호출로 충분하다.

## 4. 모듈 구조

```
src/
  main.rs        Tauri 부트스트랩, 트레이 등록, 5분 타이머
  cswap.rs       CLI 호출과 JSON 파싱
  model.rs       Account, Usage, Window, Status 타입 및 상태 판정
  menu.rs        계정 목록을 네이티브 메뉴 트리와 툴팁 문자열로 변환
  autostart.rs   레지스트리 Run 키 등록 및 해제

icons/
  tray.ico       16/24/32/48px 멀티사이즈 정적 트레이 아이콘
```

`cswap.rs`가 유일한 외부 경계다. 프로세스 스폰과 JSON 역직렬화만 담당하고
판단은 하지 않는다. `model.rs`와 `menu.rs`는 순수 함수로 구성해 프로세스나
파일시스템 없이 테스트할 수 있게 한다.

### 4.1 모듈별 계약

**cswap.rs** — 입력은 명령 종류, 출력은 `Result<CswapResponse, CswapError>`.
Windows에서 콘솔 창이 깜빡이지 않도록 `CREATE_NO_WINDOW` 플래그로 프로세스를
띄운다. 10초 타임아웃을 적용하고, 초과 시 자식 프로세스를 종료한 뒤
`CswapError::Timeout`을 반환한다. 실행 파일은 `PATH`에서 `cswap.exe`를
탐색하고, 실패하면 `%USERPROFILE%\.local\bin\cswap.exe`를 확인한다.

**model.rs** — cswap JSON을 앱 내부 타입으로 옮기고, 사용률로부터 상태 등급을
판정한다. `list --json`의 여러 필드가 선택적이므로 모두 `Option`으로 받는다.

**menu.rs** — `&AppState`를 받아 메뉴 항목 목록과 툴팁 문자열을 반환한다.
Tauri 메뉴 객체 생성은 `main.rs`에서 수행하고, 이 모듈은 구조와 문자열만
계산해 테스트 가능하게 한다.

**autostart.rs** — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 아래
`ClaudeSwapBar` 값의 등록, 해제, 존재 확인.

## 5. 데이터 흐름

```
5분 타이머 ─┐
메뉴 열림 ──┼─→ cswap list --json ─→ parse ─→ AppState
수동 갱신 ──┘                                    │
                                               menu.rs
                                        (메뉴 재구축 + 툴팁 갱신)
```

아이콘은 정적이므로 갱신 대상이 아니다. 상태 변화는 툴팁과 메뉴에만 반영된다.

계정 항목 클릭 시:

1. `cswap switch <num> --json` 실행
2. 완료 후 즉시 `cswap list --json` 재조회
3. 아이콘과 메뉴 갱신

전환이 진행되는 동안 메뉴 항목을 비활성화하고 아이콘에 진행 표시를 하지 않는다.
전환은 보통 수 초 내에 끝나며, 실패 시 6절의 규칙에 따라 메뉴에 표시된다.

갱신 요청이 겹치는 경우 새 요청을 시작하지 않고 진행 중인 요청의 결과를
기다린다. 즉 동시에 최대 하나의 `list` 호출만 존재한다.

## 6. 트레이 아이콘

아이콘은 정적이다. 앱 상태에 따라 바뀌지 않으며 런타임 렌더링도 하지 않는다.
`icons/tray.ico` 한 장을 16, 24, 32, 48px 멀티사이즈 ICO로 번들해 Windows가
디스플레이 배율에 맞는 크기를 고르게 한다.

이 결정의 대가는 사용량과 오류 상태를 아이콘만 봐서는 알 수 없다는 것이다.
모든 상태 정보는 툴팁(6.1절)과 메뉴(7절)에만 나타난다. 마우스를 올리거나
메뉴를 열어야 확인할 수 있다.

아이콘 색상으로 한도 상태를 표시하는 방안은 v2에서 다시 검토한다.

### 6.1 툴팁

```
tkddn204@gmail.com (#2)
5h  25%   리셋 4h 14m
7d  55%   리셋 2d 4h
$   90.62 / 200  (45%)
```

`spend` 필드가 없는 계정은 마지막 줄을 생략한다. per-model 한도(`scoped`)가
0%가 아닌 항목이 있으면 그 아래에 한 줄씩 덧붙인다.

Windows 트레이 툴팁은 최대 127자다. 초과하면 뒤쪽 줄부터 잘라낸다.

## 7. 트레이 메뉴

좌클릭과 우클릭 모두 같은 메뉴를 연다.

```
  ✓ 2  tkddn204@gmail.com   5h 25%  7d 55%
    1  tkddn204@gmail.com         5h  0%  7d 12%
  ───────────────────────────────────────────
  Rotate
  Best Quota
  ───────────────────────────────────────────
  Refresh now
  Open Dashboard
  Start with Windows    [✓]
  ───────────────────────────────────────────
  Quit
```

계정 항목은 라디오 체크로 활성 계정을 표시한다. alias가 설정된 계정은 이메일
대신 alias를 표시한다. `cswap disable`로 자동 순환에서 제외된 계정은 흐리게
표시하되 클릭으로 전환할 수 있다.

`Refresh now`에는 상대 시각을 붙이지 않는다. 원래는 마지막 성공 갱신 기준으로
`· 2분 전 갱신`을 표시할 계획이었으나, 그 문자열은 메뉴를 만드는 순간 구워지고
메뉴는 갱신 직후에만 다시 만들어지므로 언제 열어도 `방금 갱신`으로 읽힌다.
메뉴가 열릴 때 다시 만드는 방법으로는 고칠 수 없다 — Tauri가 트레이 클릭을
이벤트 루프로 게시하는 탓에 우리 코드는 항상 팝업이 열린 뒤에 실행되고, 그때
메뉴를 교체하면 Windows가 표시 중인 `HMENU`를 파괴한다.

사용량이 낡았다는 정보는 이미 툴팁과 메뉴 상단이 cswap 자신의 `usageAgeSeconds`를
근거로 표시하므로, 썩는 문자열을 남기느니 지우는 편이 정직하다.

`Open Dashboard`는 새 콘솔 창에서 `cswap tui`를 실행한다. 이 경우에만
`CREATE_NO_WINDOW`를 적용하지 않는다.

## 8. 실패 상태

macOS 앱의 정직한 실패 표시 원칙을 따른다. 실패를 침묵으로 처리하지 않는다.

아이콘이 정적이므로 모든 실패는 툴팁과 메뉴로만 전달된다.

| 상황 | 툴팁 | 메뉴 |
| --- | --- | --- |
| `cswap.exe`를 찾을 수 없음 | `cswap을 찾을 수 없음` | `cswap을 찾을 수 없음` + 설치 안내 링크 열기 |
| 명령 실패 또는 10초 타임아웃 | `갱신 실패` | `갱신 실패: <stderr 첫 줄>` |
| 사용량 조회 실패, 계정 목록은 유효 | 마지막 값 + `(12분 전)` | `사용량 정보 오래됨 (12분 전)` |
| 계정이 한도 초과 | 해당 창에 `rate limited` | 해당 계정 행에 `rate limited` |
| 전환 실패 | 변화 없음 | 메뉴 상단에 `전환 실패: <사유>` |

에러 메시지는 다음 성공 갱신 시 사라진다. v1에서는 토스트 알림을 사용하지
않으므로 모든 오류는 툴팁과 메뉴 안에서만 보인다.

## 9. 영속 상태

설정 파일을 만들지 않는다. v1의 유일한 영속 상태는 시작 프로그램 등록 여부이며,
이는 레지스트리 값의 존재 자체가 상태다. 갱신 간격 5분은 상수로 고정한다.

단일 인스턴스는 `tauri-plugin-single-instance`로 보장한다. 두 번째 실행은
기존 인스턴스에 갱신 요청만 보내고 종료한다.

## 10. 테스트 전략

**model.rs** — 실제 `cswap list --json` 출력을 픽스처 파일로 고정하고 파싱과
상태 판정을 검증한다. 다음 경계 케이스를 포함한다: `usage` 필드 없음, `spend`
없음, `scoped` 빈 배열, `resetsAt` 없음, 계정 0개, 활성 계정 없음.

**menu.rs** — 계정 목록으로부터 생성된 메뉴 항목 구조와 툴팁 문자열을 기대값과
비교한다. alias 표시, disabled 계정 표시, 활성 계정 라디오 체크, 툴팁 127자
절단, `spend` 없는 계정의 줄 생략, 오류 및 오래된 데이터 상태의 문구를
확인한다.

**cswap.rs** — 고정 JSON을 출력하는 스텁 실행 파일로 통합 테스트한다. 성공,
비정상 종료 코드, 타임아웃, 잘못된 JSON 네 경우를 다룬다.

**수동 QA** — 실제 전환 후 `claude` 명령을 실행해 계정이 실제로 바뀌었는지
확인한다. 이 부분은 자동화하지 않는다.

## 11. 빌드와 배포

`cargo tauri build`로 NSIS 설치본과 포터블 exe를 생성한다. 코드 서명은 v1
범위에 포함하지 않는다.

## 12. v2 이후

Tauri 골격을 유지하는 이유가 여기에 있다.

- HTML/CSS 팝오버 창으로 macOS 앱과 유사한 미터 UI 구현
- 트레이 아이콘에 한도 상태 반영(색상 변형 또는 동적 렌더링)
- `cswap auto` 백그라운드 자동 전환 토글
- 전환 및 한도 임박 시 Windows 토스트 알림
- 계정 추가, alias 편집, slot 순서 변경
